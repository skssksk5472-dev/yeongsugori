# 00. 개요 — ZALSSM (잘씀)

> 읽는 순서: 이 문서 → 02 기능·화면 → 06 디자인 → 03 API → 04 스키마 → 01 구조 → 05 OCR → 07 구현 계획.
> 막히는 점이나 새로 정한 내용은 `docs/DECISIONS.md` 에 기록한다.

## 1. 무엇인가

**ZALSSM (잘씀)** 은 영수증 사진 한 장으로 지출을 기록하는 모바일 웹 가계부이다.
현장실습생 4명이 학교 SW 개발 교육 프로젝트(CDP)로 다룰 **교육용 레퍼런스 시스템**이다.

- 멘토(사장님)가 시스템을 먼저 만들어 두고, 학생은 **설계 과정과 구조를 이해**하는 데 집중한다.
- 구조는 운영 중인 슈퍼노바와 **동일한 계층**을 따른다 (nginx → Next.js → FastAPI → MongoDB).
- 시연은 학생 PC에서 서버를 띄우고, 같은 Wi-Fi의 휴대폰 브라우저로 접속해 영수증을 촬영하는 것으로 끝난다.
- 코드는 **쉽게 읽혀야** 한다. 영리한 추상화보다 단순하고 일관된 구조를 우선한다.

## 2. 기능 범위

| 구분 | 기능 |
|---|---|
| 기초 | 회원가입, 로그인, 로그아웃, 설정(닉네임 변경, 비밀번호 변경, 회원 탈퇴) |
| 핵심 | 기본 가계부(지출·수입 입력/조회/수정/삭제, 월별 요약), 내 데이터 분석(월별 카테고리 비율, 전월 대비, 카테고리 상세) |
| 심화 | 영수증 OCR: 사진 → GPT API(프롬프트 엔지니어링) → 상호·날짜·품목·가격·카테고리 JSON → 사용자가 수정 → 저장 |

**범위 밖 (만들지 않는다):** 소셜 로그인, 이메일 인증, 비밀번호 찾기, 예산, 반복 지출, 알림, 다국어, 데스크톱 전용 UI, 실제 금융사 마이데이터 연동, PWA 설치.
여기서 "마이데이터 분석"은 **앱 안에 쌓인 내 데이터를 카테고리로 분석**하는 기능을 뜻한다.

## 3. 가정과 결정 (사용자 확인 전 제가 정한 것)

사용자가 자리를 비운 동안 질문 없이 정했다. 바꾸고 싶으면 `DECISIONS.md` 에 기록하고 바꾼다.

| # | 결정 | 이유 |
|---|---|---|
| 1 | 모바일 웹만 만든다. 기준 화면 390x844, 폭 480 이상이면 가운데 정렬한 폰 폭 컨테이너로 보인다 | 요청: 모바일 UX/UI만 |
| 2 | 지출과 수입을 모두 다룬다. 수입은 입력·조회만 있고 분석은 지출만 대상이다 | 가계부 기본 기능, 추가 작업은 거의 없음 |
| 3 | 인증은 **JWT + HttpOnly 쿠키** (슈퍼노바와 같음). 서버에 로그인 상태를 저장하지 않는다 | 사용자 결정 (2026-11-04) |
| 4 | 영수증 이미지는 서버 로컬 디스크(`UPLOAD_DIR`)에 저장한다. 저장소는 인터페이스 뒤에 두어 오브젝트 스토리지로 교체할 수 있게 한다 | 학생 PC 로컬 시연, 슈퍼노바는 Object Storage 사용 |
| 5 | DB는 **MongoDB Atlas** 가 기본이다(`.env` 의 `MONGODB_URI`). Atlas 없이 하려면 `MONGODB_URI` 를 비우고 compose의 로컬 mongo(`--profile local-db`)를 쓴다 | 사용자 결정 (2026-11-05) |
| 6 | OCR은 OpenAI 이미지 입력 모델을 서버에서 호출한다. `OCR_MODE=mock\|openai`. 키가 없으면 mock으로 동작한다 | 키 없이도 전체 흐름 시연·테스트 가능 |
| 7 | 카테고리는 서버 상수(고정 목록)이다 | 단순화, 분석 일관성 |
| 8 | 영수증의 할인은 **음수 금액 품목**으로 저장한다 (합계가 맞도록) | 지출 분석이 실제 결제액과 일치 |
| 9 | 프론트는 TypeScript + Next.js App Router + CSS Modules. 슈퍼노바 프론트와 같은 구성이다 | 슈퍼노바 확인 (2026-11-03) |
| 10 | 백엔드 폴더는 슈퍼노바의 `view·model·controller` 구조를 따른다. 매핑은 01 문서 4절 | 확인 필요 |
| 11 | 수량은 저장하지 않는다. 결과 화면에서만 표시한다 | 단순화 |
| 12 | 회원 탈퇴 시 내역·영수증·이미지를 즉시 삭제한다 (소프트 삭제 없음) | 단순화, 개인정보 최소화 |
| 13 | 닉네임 변경 화면은 시안이 없다. 비밀번호 변경(S2)과 같은 패턴으로 만든다 | 시안 생략 |

## 4. 디자인 산출물

- `design/index.html` : 모든 화면 시안 모음 (브라우저로 열기)
- `design/png/` : 화면별 PNG (2x). **구현 후 같은 화면과 비교해 맞춘다.**
- 화면 ID(A1, H1, O3 ...)는 02 문서와 동일하다.
- 시안의 목업 데이터는 시드가 아니다. 데모용 시드는 07 문서의 `scripts/seed` 항목을 따른다.

## 5. 교육 연계

| 주차 | 이 프로젝트에서 보여줄 곳 |
|---|---|
| 1주 | 아키텍처 구성도(01), 계층 구조, Git 협업 흐름(07) |

## 6. 용어

| 용어 | 의미 |
|---|---|
| 내역 (transaction) | 가계부 한 줄. 지출 또는 수입 |
| 영수증 (receipt) | 업로드한 영수증 이미지 + 분석 결과 메타 |
| 품목 (item) | 영수증의 상품 한 줄. 저장하면 내역 한 건이 된다 |
| JWT 토큰 | 로그인한 사용자(`uid`)와 만료 시각을 담아 서버 비밀 키로 서명한 문자열. 쿠키에 담겨 오간다 |
